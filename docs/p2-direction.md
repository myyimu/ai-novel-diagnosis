# P2 方向：从判定到成长

本文档沉淀 2026-08-19 的产品战略讨论（立项审稿 P1 闭环之后的四轮推演），并据此设计 P2 开发方向。
产品教义（[`product-doctrine.md`](./product-doctrine.md)）把主线定义为"把成熟编辑的工作过程蒸馏成
作者可反复使用的写作教练"——本文回答的是：**教练在"判定"之外还差哪三种姿态，以及 P2 按什么顺序补齐它们。**

> 结论先行：P2 的主题是**从"可反驳的判定"走向"可积累的成长"**。三个新增姿态——教师（引导而非宣判）、
> 透明管线（过程可见而非黑箱等待）、会诊（多视角而非单一声音）——全部构建在既有病历体系之上，
> 不新增自主 AI 行动者。作者仍是唯一有目标的 agent。

## 1. 战略结论沉淀

每条结论记录理由与被否方案，防止原样重提（沿用 [`premise-review.md`](./premise-review.md) §2 体例）。

### 1.1 核心价值定位：卖证据与劝退，不卖鼓励与代写

价值三支柱：**立场**（编辑不是写手，裁判与球员分离，doctrine 明文否决过 Writer Agent）；
**纪律**（证据锚定是结构性的——子串/偏移硬校验，不是提示词请求，指控钉不到原文即作废）；
**主权**（模型判断必须经作者裁决才落病历，P1 的确认面板即此纪律的产物）。
风险前移是单次价值（五分钟毙掉不成立的发动机 vs 三十章写崩）；病历复利是持续价值
（复诊差值、prompt 归因、方法论卡）。

边界（诚实记录）：核心风险是**判断质量**本身——结构、锚定、病历都是让判断*可信*的机制，
判断*质量*至今只过小规模人工验证（premise-review.md §6 的维护规则即为此设）。

### 1.2 "模型判断有用"命题的澄清：弱前提，可证伪

被否的强前提："AI 审美比人准"——审美层是哈姆雷特空间，该前提是伪命题，产品也从不押注它。

实际押注的弱前提：**与模型争论的成本低于写崩三十章的成本，且争论留下可追踪的记录。**
判断分三层，主观度递增、产品投入递减：

| 层 | 例子 | 性质 | 产品投入 |
| --- | --- | --- | --- |
| 结构层 | 欲望是否存在、冲突是否升级、时间线自洽、引文可定位 | 近可验证 | 最重（锚定、审计、体检） |
| 工艺层 | 钩子是否有代价、节奏适配平台 | 品类共识 + 数据可观测（追读/完读快照） | 中（rubric、quick-review） |
| 审美层 | 值不值得写、好不好 | 不可判定的主体空间 | 只做可反驳重述，不做宣判 |

可证伪路径已内建：复诊 V1/V2 差值 + prompt 归因率把"建议对不对"转换为
"采纳建议的稿子在作者自己关心的指标上动了没有"。已知缺口两条：**运行间稳定性未测**
（同一灵感两次审稿判定漂移则每次判定再合理也是噪声）；**品味错配**
（模型的编辑先验是语料平均值，细分读者群要的可能是平均值眼里的俗套——
`author_intent` 逃生闸门是兜底不是解决）。

### 1.3 教师姿态：同一病历体系的第二个产品姿态

编辑守护门槛（值不值得写），教师负责发展（怎么变精彩）。教师不是新架构，是新交互姿态，
其机制胚胎全部已在库中：

| 教学手艺 | 既有胚胎 | P2 缺口 |
| --- | --- | --- |
| 提问，不给答案 | `readerHookQuestion`、方法论卡 `selfCheckQuestion`（现为展示字段） | 构成对话：模型抛问 → 作者作答 → 评判回答是否强化该层 |
| 诊断→练习→复查循环 | 初诊 / nextPrompt / 复诊（章节级闭环已在跑） | 提到灵感级：立项多轮引导 |
| 最近发展区：每轮一事 | `severity` / `blocksNextStep`（原料已有） | 编排：一轮只指认一个要害问题，其余收起 |
| 让思考可见 | 编辑版重述契约（worked example） | **作者版契约**：作者自己重述，写不出即未懂自己的故事（费曼测试），对比即理解度 |
| 终点是让自己多余 | 方法论卡（作者沉淀自己的检查清单） | 诊断前先用作者自己的卡自检，自评先于专家评估 |

护栏：教师是 warm demander（热忱但标准不降），不是啦啦队——鼓励的合法形式已有判例
（升级方向必须写"保留元素"）；每轮评判同样锚定证据、可反驳；进病历的只有作者写下的东西。

被否方案：教师模式替作者产出改好的冲突/大纲——那是写手，且诱导推倒重来（§1.1 立场支柱）。

### 1.4 多 agent 立场：多视角，不多行动者

角色盘点：审稿编辑、初诊医生、整书体检员、二审复核员、研究馆员、复诊医生、平台顾问（雏形）、
教师（P2 新增）——约八个角色雏形。但**多角色 ≠ 多 agent**：现有角色都是作者在确定流程节点
召唤的、单次调用的、schema 约束的专科医生，由代码确定性编排，共享一份病历。

唯一被本产品验证有价值的多 agent 形式：**对抗性验证**（二审复核员——一个调用专门反驳另一个，
findingId 回显防串、置信度门槛、降级不阻塞）。P2 沿此扩展两项：**会诊**
（低置信度或作者不服时召唤独立第二审稿人，一致则判定更硬，分歧则分歧本身呈现给作者）与
**分歧披露**（quick-review 与 story-audit 对同一章的矛盾结论显式检测并交作者裁决，不静默各说各话）。

被否方案：自主 agent 链（主编 agent 编排其余、agent 间自由协商、替作者综合结论）。理由：
agent 对话天然脱锚（协商产物是模型间互引的文本，恰恰产出"头头是道但钉不到原文"的批评）；
谄媚在 agent 间传染（把对抗层换成合谋层）；责任主体消失（"系统认为"让作者连反驳谁都做不到，
瓦解作者裁决落库纪律）；错误与账单在链上复利。

架构原则：**编排永远留在代码里**（NestJS service，确定性、可测试、可审计）；模型调用保持角色化。
角色的正式定义 = 提示词 + 证据要求 + 输出 schema + 病历读写权限（ai-core 契约 + api 模块划分
已是这个形状的隐性版本，P2 只在需要会诊时显式化）。

### 1.5 过程可见性：事件级透明，不是 token 级流式

问题诊断：长文本分析期间作者只能被动等待——真实的 UX 债务。但解法不是对话产品的 token 流式：
诊断产品的交付物是完整、锚定、可反驳的判定，把半成品判断流到屏幕上（作者截屏、反应、改稿，
十秒后该指控被服务端剔除）**违反产品自身的认识论纪律**。

正确目标是**过程可读**（事件级），且骨架已在库中：job `progress`（章节级真实事件）、
`partialResult` 字段（架构早已预留部分结果概念）、finding 四态里的 `candidate`
（"初核未复核"本来就是产品词汇表中的合法认知状态）。设计三条：

1. **逐章浮现的初核发现**：map-reduce 每章完成、通过机械锚定（快且确定）的发现即推送展示，
   挂"初核"徽章，LLM 复核后升级、被拒则划掉并披露。等待变成看着病历一页页长出来。
   红线：未过机械锚定的一条不显示。
2. **进度承载教学**：等待期间滚动的是"正在检验第 2 层：主角想要什么，是否具体且强烈——
   为什么查这个"（`PREMISE_LAYER_META` 的问题文案是现成的）。等待时间 = 学习编辑方法的时间。
   红线：只显示管线真实事件，模型沉默就诚实显示"生成中（已等待 N 秒）"，不伪造步骤——
   与阶段轨"禁止估算进度"同一条纪律。
3. **对话入口挂在病历，不挂管线**：跑到一半的过程不开放自由对话（插话要么不影响结果是伪交互，
   要么改变在跑的分析破坏 reviewId 溯源）。两个诚实形态：**过程中**只读探视 + 显式打断
   （取消并以新的 `diagnosticFocus` 重跑——不跟跑着的进程聊天，是中止后带新指令重来）；
   **报告后**就这份报告提问（"为什么说我的冲突是一次性的？"，回答锚定报告证据与原文——
   判例是研究侧栏的 `askResearchLibrary` 带引用问答）。

被否方案：把 ChatGPT 式聊天窗嵌进诊断流程——会把结构化、可反驳、有出处的编辑意见
退化成"听起来有道理的闲聊"。

## 2. 成功指标：毕业率，不是判断正确率

教师姿态的交付物是**作者内化的编辑器**，因此 P2 的北极星指标是依赖递减：

- **复发率**：同一 issue 类别（如章末钩子无代价）在后续章节的出现率是否随诊疗轮次下降。
- **自检命中率**：诊断前作者用方法论卡自检时，先于系统发现的问题比例。
- **契约收敛度**：作者版契约与编辑版契约的差距（理解度代理）。
- 护栏：不以会话数、生成量、判定总数制造伪进步（doctrine 看板条款）。
- 评测门禁不变：本指标的改善不构成 doctrine §有效性评测门禁 的豁免——判断质量的大规模
  验证（240–400 样本盲标等）仍是独立前置义务。

## 3. P2 路线

按"便宜且是后续上车口 → UX 债 → 旗舰 → 深水区"排序。每个任务记录落点与验收，
实施时逐项转成独立落成记录（premise-review.md 体例）。

### P2-T1 报告问答（诊断报告的锚定问答）——已落地（2026-08-19）

- **做什么**：每份诊断报告（quick-review / premise review / story-audit 摘要）底部加问答入口，
  回答必须引用报告内证据与原文锚点，答不了就明说。
- **落点**：api 新问答端点（模式复制 `askResearchLibrary`：问题 + 上下文文档集 + 引用约束）；
  web 报告组件底部入口。
- **为什么第一个**：最便宜（单次调用 + 已有引用问答模式）；是 T3 教师对话的上车口
  （报告问答与引导对话是同一机制的两个深度）；立刻缓解"报告是单向宣判"的问题。
- **验收**：回答带报告内引用；无据可答时明确拒答而非编造；不修改原报告任何字段。
- **落成记录**：端点为无状态 `POST /analysis/report-qa`（报告内容由客户端携带，问答结果不落库）；
  引用锚定采用 premise-review 的子串规则——模型引用必须逐字命中报告内文或作品原文，
  未命中的引用被服务端移除并写入 gaps 披露；模型输出解析失败时返回诚实披露而非 400。
  契约 `ReportQaResult` 在 ai-core（含报告种类与引用来源的封闭枚举），web 侧三处报告
  （立项审稿 / 章节初诊 / 故事体检）底部均挂 `ReportQaPanel`，问答为会话级状态不进病历。
  验证：ai-core typecheck/lint/test(58)/build；api typecheck/lint/test(323)；
  web check/test(126)/build。提交 `4dd4611`（契约）、`29fb833`（端点）、`8a63cf2`（面板）。

### P2-T2 过程可见性（黑箱等待 → 事件级透明）——已落地（2026-08-19）

- **做什么**：① book 分析的 `partialResult` 增补逐章初核发现（过机械锚定后才入）；
  ② web 渐进渲染初核列表（candidate 徽章，复核后升级/划掉）；③ premise 等待 modal 换成
  逐层检验文案（第一版前端按层序展示"正在检验什么"，真实事件接入后替换）；
  ④ 打断重跑入口（复用 `diagnosticFocus`）。
- **落点**：api job 进度/partialResult 增补；web job 轮询渲染 + `PremiseReviewCompose` modal。
- **验收**：界面上的每个进度项都对应管线真实事件；未过锚定的发现零展示；
  初核态与复核态视觉可区分且被拒时披露。
- **刻意不做**：token 流式（§1.5）；等待期间的自由对话（§1.5）。
- **落成记录（首批：③④ + 章节级真实事件）**：premise 等待 modal 换成四层检验教学清单
  （`PREMISE_LAYER_META` 的问题文案），明示"这是检验维度不是实时进度"、保留诚实的已等待秒数，
  不伪造任何步骤完成事件；api `partialResult` 新增 `lastCompletedChapter`
  （order/title/phase/completedAt），只在章节 map 真正完成时写入；web 运行卡新增
  深拆进度条与"最近完成"行（只消费该真实事件，无事件时明说等待中），并以
  "不再等待"按钮打断跟随——轮询静默停止、文案披露任务仍在服务端继续、可从历史任务重开。
  验证：api typecheck/lint/test(324)；web check/test(130)/build。
  提交 `2914da6`（等待 modal）、`b40bf3b`（lastCompletedChapter）、`edbd1ff`（渲染与打断）。
- **落成记录（深水区：①②逐章初核）**：map 每章完成时从该章 map 产物提取「章节初核卡」
  进 `partialResult.candidateChapterCards`——锚定摘录（map 归一化时已过 `locateQuoteRange`
  机械校验，不命中即丢弃）+ 未复核的一句话摘要 + 风险/伏笔信号（各封顶 2 条）。
  **红线执行在章级**：没有任何锚定原文的章节一张卡都不出；且信号与锚点是章级关系、
  非逐条锚定——卡内分栏存放，web 渲染（`ChapterCandidateCardList`，最近完成在前、
  只渲染最近 12 章并披露截断）把两者分开标注，「初核」徽章与体检报告里的
  candidate/verified 状态视觉可区分，复核计数（含被拒）在体检报告中披露。
  深拆完成覆盖同章轻索引卡；服务端只保留最近 80 张以约束持久化体积。
  诚实边界：初核卡与体检报告的最终发现是两种对象（章级信号 vs 跨章判定），
  不做逐条"升级/划掉"映射，界面明示"复核以体检报告为准"。
  逐信号锚定需升级 map schema（给信号配 quote 引用），留作后续。
  验证：api typecheck/lint/test(330)；web check/test(134)/build。
  提交 `1b2db16`（初核卡提取与入列）、`0994a44`（渐进渲染）。

### P2-T3 立项引导对话（教师姿态旗舰）

- **做什么**：`/diagnose/idea` 增加"引导模式"：结构化多轮（上限约三轮），每轮针对最薄弱审计层
  抛一个问题，作者回答被要求引用自己的原文，模型评判该回答是否强化此层（升/降层判定并给理由），
  结束产出**作者版契约**，随 reviewId 落病历，与编辑版契约并列对照。
- **落点**：ai-core `PremiseDialogue` 契约 + changeset；api 对话表 + 端点（挂 reviewId）；
  web 引导模式面板 + 作者版契约渲染。
- **前置**：问题库提示词质量必须先人工验几轮（premise-review.md §6 纪律）——这是本路线
  真正的难点，工程量小于 T2。提示词草案（ASK/JUDGE/CONTRACT-REVIEW 三份 + 编排状态机 +
  人工验证脚本与判废标准）见 [`premise-dialogue-prompts.md`](./premise-dialogue-prompts.md)，
  验证通过前工程不动工。
- **验证进度（2026-08-19，两轮真实模型，已通过）**：首轮 AI Horde 匿名池 gemma-4-31b
  4/5 场景通过（场景 3 与 CONTRACT-REVIEW 因通道截断未取得判定）；第二轮在生产级通道
  qwen3.8-max（百炼 compatible-mode）全场景复验通过——谄媚检测顶住反驳不翻转、代写诱惑
  零渗出、CONTRACT-REVIEW 收紧后复验通过，判废标准零命中。验证中收紧两处提示词
  （ASK 单问号+不虚构原文细节；CONTRACT quoteAuthor 单字段连续片段）。**工程动工前置
  已满足**。完整记录见 [`premise-dialogue-prompts.md`](./premise-dialogue-prompts.md) §7
  与 [`premise-dialogue-validation-report.md`](./premise-dialogue-validation-report.md)。
- **验收**：每轮评判锚定作者原话；作者版契约由作者写出（模型只提问不代写）；
  对话轮次有硬上限；产出进病历且可导出。
- **刻意不做**：无上限自由聊天；模型替作者填契约字段。
- **落成记录（2026-08-19，已落地）**：三层全部落地。ai-core `premise-dialogue.ts`
  （层选择状态机 missing→weak/confidence 升序、三轮硬上限、三组 prompt 构建、
  quoteAuthor 子串锚定与拒绝语义：quote-not-found 终局 / model-failed 可重试，
  87 项测试）；api `premise-dialogue` 模块（`analysis/workspace/premise-dialogue`
  下 start/get/answer/judge/next/finish/contract 七端点、`premise_dialogue_sessions`
  表 jsonb 落库、mock 短路按构造即可锚定，spec 覆盖锚定拒绝/拼接拒绝/硬上限收束）；

### P2-T4 会诊与分歧披露（多视角）

- **做什么**：① premise verdict 低置信度或作者标记不服时，召唤独立第二审稿人
  （不同提示词立场，可选不同模型），一致/分歧连同两份理由呈现给作者；
  ② quick-review 与 story-audit 对同一章的矛盾结论做显式分歧检测，交作者裁决。
- **落点**：api 会诊端点（对抗性验证模式，复用 verifier 形状）；web 分歧呈现组件。
- **依赖**：T1 的问答基建（呈现口径）与置信度字段的语义澄清（doctrine：confidence 是证据完整度
  提示不是正确概率——会诊触发条件必须按此措辞）。
- **验收**：分歧不静默消解，作者能看到两方各自锚定的证据；会诊结果不覆盖原判定而是并列。
- **刻意不做**：agent 间自主协商（§1.4）；会诊结论自动裁决。
- **落成记录（2026-08-20，已落地）**：两个子任务三层全部落地。① premise 会诊：
