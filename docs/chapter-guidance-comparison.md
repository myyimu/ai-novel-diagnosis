# 章节引导与对照

这项功能用真实稿件检验一个问题：作者确认的引导计划，是否比直接按原始目标改稿更有帮助。工程验收通过，只说明流程能够运行；是否值得继续使用，由真实稿件和阅读反馈决定。

## 使用

入口：书籍工作区 → 打开一个章节 → **引导与对照**。

1. 使用当前正文或粘贴稿件，填写本次目标、必须保留的内容、必要设定与前情。保存后原稿和目标固定，后续修改不会覆盖它们。本次支持 50–12,000 字。
2. 在现有 AI 设置中选择可用模型。围绕稿件交流，最多六轮。可以请求澄清问题、比较方案、质疑现有诊断；不必接受模型意见。原文引用会核对是否实际存在，但这并不证明模型解释正确。
3. 编辑并确认修改计划。计划确认后固定；想改变目标或方案时另建对照。
4. 分别生成普通改稿和引导改稿，每条路线最多两轮。第一轮都从原稿开始，第二轮只使用自己路线的上一轮正文。普通路线收到原始目标、保留项与上下文；引导路线额外收到作者确认的计划。引导对话可选择参考现有诊断，两条改稿路线都不会直接收到诊断或对话记录。
5. 选择任意两个版本，打乱 A/B 顺序阅读。比较两条路线的相同轮次更容易解释差异；也可以比较原稿与候选。填写偏好、无明显差别或无法判断以及具体理由，再揭晓来源。原稿、中间稿均可胜出。
6. 导出正文或整次对照记录，也可载入所选版本作为章节草稿，再重新诊断。载入不会自动把旧问题标为已解决。如果当前正文有未纳入本次对照的修改，先另建对照保存它，或下载候选后手动合并。

历史对照按书籍与章节标题读取，刷新后可恢复。当前版本尚未采用稳定章节 ID 关联：同书同名章节会共享列表，重命名后的历史可以通过恢复原名查看，或提前导出备份。

## 如何判断有用

先选几份自己熟悉、目标明确且类型不同的真实稿件。记录哪里改善、哪里退步、保留项是否被破坏，以及引导是否帮自己做出了更清楚的决定。允许记录“没有帮助”，也保留好稿无需修改的例子。

作者可能认出自己的稿子；页面隐藏来源并不构成严格盲评。可将匿名 A/B 文本交给独立读者阅读，再记录其判断。单次偏好不能证明普遍有效，模型分数也不能代替阅读反馈。两条路线采用相同的请求设置，首次生成后锁定这些设置；自动服务线路仍可能更换实际模型，模型标签会提示这一限制。引导路线额外耗费的交流时间，也应计入实际使用成本。

当前范围是一个章节的可控比较，没有接入外部小说创作项目，也没有全书自动循环改写。两轮后应回看具体收益，再决定是否需要更多自动化。

## 运行与数据

- 使用现有 Web/API 启动方式，无新增运行时依赖。
- API 新增 `/analysis/chapter-experiments` 和 `/:id/actions`，数据保存在 `chapter_experiments`。与当前工作区一致，这些是本地应用的公开接口，不提供多用户身份隔离。
- PGlite 开发模式随 API 启动建立新表。Postgres 环境按现有迁移流程运行 `pnpm --filter api db:migrate`，新增迁移为 `0005_chapter-experiments.sql`。没有对实际 Postgres 数据执行迁移。
- 原稿、设定、对话、计划、各轮全文和人工判断持久化；模型密钥不写入对照记录。导出的 JSON 包含这些创作内容，应按稿件保管。
- 并发写入使用版本号检查；旧请求不覆盖新记录。模型调用失败、伪造引文、无改动输出或不完整 JSON 都不新增成功版本，已保存内容保留。请求期间离开页面后，已完成并保存的结果可回来重新载入；这不是可靠后台任务队列。

## 验收范围

自动测试覆盖 HTTP 参数校验、原稿保留、路线独立、两轮上限、方案和模型设置锁定、引文核验、不完整输出拒绝、并发写入保护、持久化与对照页面的来源隐藏。

浏览器验收使用隔离数据库和固定测试响应，检查引导、确认方案、双路线生成、保存阅读判断、刷新恢复与载入草稿。固定响应只用于验收交互，不能据此宣称真实模型的改稿质量已被验证。
