# desktop-shell — Agent Guide

Electron desktop shell. Stack: **Electron 41 + TypeScript (strict) + inversify (DI) + tsdown (build) + electron-log + electron-store + oxlint/oxfmt**.

The desktop project is a **shell only**: it owns the window, the sidecar lifecycle, and packaging. There is **no renderer code and no IPC/preload layer here** — all UI lives in `apps/web` (Next.js), loaded over HTTP, and talks to the API sidecar like any browser client would.

## Project layout

```
apps/desktop/
├── apps/electron/           # The single Electron app (main process only)
│   ├── src/
│   │   ├── index.ts         # Entry: inversify container, single-instance lock, lifecycle
│   │   ├── app.ts           # ElectronApp orchestrator: startup order, error surface
│   │   ├── constants/       # APP_URL etc.
│   │   ├── core/window.ts   # BrowserWindow factory base class
│   │   ├── services/
│   │   │   ├── env.ts             # Sidecar env vars (API 127.0.0.1:3001, Web 127.0.0.1:3000)
│   │   │   ├── paths.ts           # Runtime path resolution (dev vs packaged)
│   │   │   └── sidecar-supervisor.ts  # Packaged mode: API → /health → Next standalone
│   │   ├── utils/
│   │   ├── vendor/           # ElectronLogger / ElectronStore wrappers
│   │   └── windows/main.window.ts   # Main window, startup status page, bounds persistence
│   ├── script/               # assemble-sidecars.mjs, package.mjs, release.mjs
│   └── tsdown.config.ts
├── package.json              # Workspace commands (check = lint + format:check + build)
└── pnpm-workspace.yaml
```

## Architecture rules — NEVER violate

- **No business logic in the shell.** Diagnosis state, manuscript versions, methodology cards — all owned by Web/API contracts. The shell never duplicates them.
- **No preload / IPC bridge.** `webPreferences` is `contextIsolation: true, nodeIntegration: false` with no preload script. Do not reintroduce one; pages use plain HTTP against the sidecars.
- **Startup order is owned by `ElectronApp.init()`**: startup status page → sidecar supervisor (packaged mode only) → load `APP_URL`. Dev mode expects the workspace `pnpm dev` services to already be running.
- **Sidecars bind loopback only** — never expose desktop sidecars to the LAN.
- `apps/electron/sidecars/` is generated by `assemble` — never hand-edit, never commit fixes into it.

## DI conventions (inversify)

- Classes are `@injectable() @provide()`; `index.ts` loads them all via `buildProviderModule()` into a singleton-scoped container.
- Constructor-inject collaborators (`@inject(MainWindow)`); no manual wiring, no service locators.
- New service? Create the class with decorators — it lands in the container automatically.

## Quality gates

```bash
pnpm --filter desktop check    # lint + format:check + build (tsdown)
```

All must pass before declaring a change complete. There is no separate typecheck script — `build` (tsdown) is the compile gate.

## Common operations

| Task | Command |
|------|---------|
| Dev run (needs workspace `pnpm dev` first) | `pnpm --filter desktop dev` |
| Build sidecars from outer web/api/core | `pnpm --filter desktop assemble` |
| Build the Electron bundle | `pnpm --filter desktop build` |
| Produce the Windows EXE | `pnpm --filter desktop release` (runs from `apps/desktop`) |

Note: this machine lacks symlink privilege (no Windows Developer Mode), so icon editing in the release pipeline is off by default.

## Process boundary rules

- **Main process (`apps/electron/src`)**: Node + Electron APIs only. No DOM, no React, no fetch-into-page logic.
- **Renderer**: is the web app. Anything user-facing belongs in `apps/web`, not here.
- When a feature needs a new window (e.g. an about dialog), extend `windows/` on the `Window` base class — keep it presentation-thin.
